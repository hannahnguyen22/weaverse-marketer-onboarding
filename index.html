Your three takeaways

Understand what Weaverse does, what merchants can edit themselves, and when a developer is needed. You do not need to know how to code to follow this guide.

01 / The idea

A custom storefront.
A visual way to update it.

A storefront is the website a shopper browses. Shopify provides commerce capabilities, including products, inventory, and checkout. A traditional Shopify store often uses a ready-made theme to present those capabilities.

Some teams build their own storefront instead. This is called headless commerce: the shopper-facing website is built separately from the commerce system behind it. Hydrogen is Shopify’s framework, a toolkit developers use to build that custom storefront.

Building and changing a Hydrogen storefront takes development work. A marketer should not need a developer to replace a campaign headline every time. Weaverse adds visual editing, so the team can make routine content and layout changes using what developers have already made available.

What Weaverse does

Makes sections editable

Connects developer-built storefront sections to visual editing controls.

What merchants edit

Content & layout

Update available fields and arrange existing sections in Studio.

When developers help

New capabilities

Build new section types, editing fields, integrations, and behavior.

A section is a page building block, such as a large opening banner (a “hero”), a product grid, or a testimonials area.

02 / The whole picture

Four names. Different jobs.

Keep the destination straight: Weaverse edits the connected Hydrogen storefront. It does not edit the Shopify Online Store’s Liquid theme. Liquid is the template language used by traditional Shopify themes.

03 / Choosing the approach

Visual editing, built for Hydrogen.

The difference lies in the foundation and how the team works. Weaverse brings visual editing to a Hydrogen storefront: developers keep technical control, while marketers and merchants edit the parts already set up for them.

Three approaches, with different foundations. Conventional page-builder capabilities vary by app.

Weaverse combines a developer-controlled Hydrogen storefront with day-to-day visual editing for the business team. The best fit depends on the store’s needs and the team maintaining it.

04 / Working together

One storefront. A shared workflow.

Developers

Build the Hydrogen storefront and reusable components. Decide which fields and layout options people can edit. Maintain integrations and ship code changes.

Agencies

Can act as the implementation partner: designing the storefront, building sections, and handing an editable setup to the merchant’s team. Responsibilities depend on the engagement.

Merchants

The businesses and people running the store. Set commercial priorities and manage storefront content using the available editing capabilities.

Marketers

Turn campaign briefs into pages using existing sections. Update messaging and images, arrange content, and check how the result looks before saving.

These roles describe a practical division of work, not product permission levels. Agency responsibilities are an illustrative team arrangement.

05 / Find your way around

Meet Weaverse Studio.

These five area names follow the official interface tour. The Inspector contains controls for the selected item.

1 Top Bar: Page and Store Context

Select a page and its storefront context. Language and store URL controls depend on the project. The connected project’s save or publish action belongs to this workflow.

2 Left Sidebar: Outline, Sections, and History

Browse the page outline, select or reorder sections, add registered sections, and access saved versions.

3 Preview Canvas

View the connected storefront, select visible sections, and check desktop, tablet, or mobile layouts.

4 Right Panel: Inspector

Edit the selected item’s content and available styles. Theme Settings contains developer-defined global options such as colors and typography, which can affect the whole storefront.

5 Studio Settings

Find workspace preferences, project details, preview URL configuration, recent activity, and theme information. These are separate from global theme design settings.

06 / A campaign in practice

Practice with the Studio demo.

The Demo Playground opens a Home page preview of the Pilot storefront. Use its existing sections to practice a seasonal campaign update. These names were checked in the live demo on 5 Nov 2026.

  1. Start on Home page using the top-bar page selector. The preview URL shows pilot.weaverse.dev.
  2. Expand Slideshow, then the first Slide in the left sidebar. Select its Heading, initially “Dress for the life you want”.
  3. Edit Content in the Inspector to try a campaign headline such as “Your new-season edit”. Select the parent Slide, then use Background image in the Background group to change its image. The Heading item has its own separate controls.
  4. Reorder existing sections in the outline. For example, bring Featured collections before Featured products to lead with collections.
  5. Switch the preview to mobile with the device control above the canvas. Check text wrapping, image cropping, and section order.
  6. Finish the practice without assuming it is published. No Save or Publish button was visible in the demo’s top bar during this review. In your team’s connected project, save changes and follow its publishing process.

07 / Know the boundary

Edit what exists.
Ask for what is missing.

React is a library developers use to build website interfaces. A React component is a reusable piece of that interface. Developers create and register these components in the storefront, then define a schema: a description of the editing controls that Studio should show.

Merchants & marketers can…

  • Change exposed text and image fields.
  • Add, remove, and reorder available sections where the setup allows.
  • Adjust available style and global theme settings.
  • Preview and save content changes.

Bring in a developer to…

  • Create a new kind of section.
  • Add a missing field, such as a hero subheading.
  • Add a new global setting.
  • Build new functionality or integrations.
Component code → repository

The repository is where developers keep and track code. New code goes through their deployment process.

Edited content → Weaverse

Page content and settings are saved in Weaverse. Routine content edits do not inherently require a Git commit or a new code deployment.

A Git commit records a code change; a deployment releases code to the running website. Saving content in Studio is a different action. Confirm your project’s review process and how saved changes become visible.

A useful handoff

“I can change the hero headline, but this campaign also needs a countdown. Can we add a countdown section and its editing controls?” That describes a new capability clearly.

Source notes & points to confirm
  • Content vs. code releases: the supplied PDF explicitly separates Studio content publishing from developer code deployment. “How Weaverse Works” broadly says production changes deploy through a CI/CD pipeline (an automated code-release process). This guide uses the PDF’s explicit distinction and flags the broader wording here. Confirm the team’s save/publish process.
  • Preview sizes: the PDF mentions desktop and mobile; the interface guide also lists tablet. This walkthrough uses desktop and mobile. Available controls should be checked in the current project.
  • Performance and accessibility: source material includes broad benefit claims. This guide makes no guarantee of loading speed, accessibility, or freedom from vendor lock-in. Storefront outcomes depend on implementation.
  • Comparisons and roles: the three-approach table gives qualified, general context rather than a feature audit of named page builders. Agency responsibilities illustrate a possible team arrangement.
  • Project-dependent controls: section libraries, editing fields, global settings, and review/publish behavior depend on the storefront setup. Ask the team which workflow applies before a real launch.
